# 复杂地表热红外辐射传输模拟器TIRT

项目地址：[https://github.com/bianzj/tirt](https://github.com/bianzj/tirt)

> TIRT 是一个面向植被、地形和城市复杂地表的热红外方向性辐射传输模拟器。它把场景结构、组分温度、材料光谱、太阳几何和观测几何放到同一个可重复的前向模拟框架中，用于回答一个关键问题：在给定的波长和观测方向下，传感器究竟看到了哪些地表组分，以及这些组分如何共同形成最终的热红外信号？

**关键词：** 热红外遥感、方向性辐射传输、亮温、发射率、植被冠层、复杂地形、城市热环境、多角度观测

## 从一个温度到一组方向性观测结果

热红外遥感经常被简单地理解为“测量地表温度”。但在真实观测中，传感器接收到的并不是一个与方向无关的温度数值，而是由地表不同组分、不同温度、不同发射率以及观测几何共同决定的热红外辐射。即使同一块地表，在不同观测角度、不同太阳位置和不同波段下，也可能表现出明显不同的辐亮度和亮温。

TIRT（Thermal Infrared Radiative Transfer）就是为处理这一类问题而设计的方向性热红外辐射传输模型。它以波长、太阳几何、观测几何、地表结构、植被结构、组分发射率和组分温度为输入，计算观测方向上的热红外辐亮度、亮温以及相关的组分信息。模型既可以用于简单的平面地表，也可以用于坡面、复杂地形、城市建筑和街道植被耦合场景。

TIRT 的核心思想并不复杂：先把场景拆分成具有明确物理意义的组分，再根据每个组分在某一观测方向上的可见性、遮挡关系和方向性贡献，计算最终传感器接收到的热红外信号。这样的结构使模型既能够保持物理解释性，也能够方便地扩展到新的场景类型。

换句话说，TIRT 不把“地表温度”当作一个脱离场景的常数，而是把它放回真实的观测条件中。一个亮温结果只有在波长、发射率、组分温度、太阳位置和观测方向都明确时，才真正具有可解释性。TIRT 的价值，正是把这些因素组织成一条可以检查、可以复现、可以扩展的计算链。

## TIRT 的三个核心价值

### 1. 场景结构清楚

TIRT 用 Surface mode 表示地表结构，用 Vegetation type 表示植被结构。平面、坡面、复合地形和城市建筑可以与裸土、均质植被、垄行作物和离散树冠组合。用户不需要把所有复杂性塞进一个平均参数，而是可以从 Plane + Bare soil 开始，逐步增加坡度、冠层、建筑和街道结构。

### 2. 输入输出可追溯

所有关键参数集中在 `input.csv` 中，包括场景、角度、波长、发射率和热状态。输出以“观测方向 × 波段”为基本记录单位，并保留场景标签、太阳角度、观测角度、各组分发射率、辐亮度以及亮温。一次模拟不仅能得到一张图，也能保留完整的计算依据。

### 3. 既适合探索，也适合批处理

GUI 提供三维场景预览和方向性图形，适合交互式检查；根目录的 `run()` 函数适合脚本、参数扫描和批量模拟；同一套 `input.csv` 可以在网页、命令行和 Python 环境中复用。这让 TIRT 同时适合科研原型、教学演示和可重复的计算流程。

## 为什么需要方向性模型

传统的单温度表达方式通常默认地表是均匀、平坦并且具有相同的热状态。然而，植被和城市地表很少满足这些假设。

在植被场景中，太阳照射的叶片、阴影叶片、土壤背景和冠层空隙可能具有不同温度。观测方向改变后，传感器看到的叶片比例、土壤比例和冠层遮挡关系也会改变。因此，同一块植被的亮温可能随观测天顶角和方位角发生系统变化。

在城市场景中，屋顶、墙壁和街道的朝向与受光条件完全不同。屋顶通常更接近水平面，墙壁具有明显的法向方向，街道则受到周围建筑遮挡和天空可见度的影响。城市热红外信号因此不是简单的“建筑平均温度”，而是多个建筑和地表组分经过方向加权后的结果。

TIRT 通过明确记录太阳天顶角 SZA、太阳方位角 SAA、观测天顶角 VZA、观测方位角 VAA 以及相对方位角 RAA，使这些方向变化能够进入计算，而不是被平均成一个固定温度。

## TIRT 可以运行哪些场景

TIRT 的统一入口支持四种地表结构和四种植被类型。两者可以组合使用，形成一组具有清晰含义的复杂场景。

### 四种 Surface 模式

**Plane：平面地表**

Plane 是最基础的参考场景。地表被视为平坦、连续的水平面，可以组合裸地、均质植被、垄行植被或离散树冠。它适合用于模型初步验证、单因素敏感性分析以及与理想化理论结果进行比较。

**Slope：单一坡面**

Slope 在平面基础上加入坡度和坡向。坡面法向不再固定指向天顶，因此太阳入射角、观测投影关系以及方向性辐射都会发生变化。通过调整 slope angle 和 slope aspect，可以研究朝向、坡度和观测方向对热红外辐射的影响。

**Terrain：复合地形**

Terrain 用多个地形层或等效地形单元描述更复杂的地表起伏。输入中可以配置地形高度、半径和空间密度，模型据此构造具有遮挡和方向变化的地形场景。Terrain 适合用于山地、起伏地表和复杂背景条件下的方向性模拟。

**Urban：城市建筑与街道**

Urban 是 TIRT 中最具应用价值的场景之一。城市场景至少包含屋顶、墙壁和街道三个具有不同几何属性的组成部分。屋顶主要表现为较接近水平的面，墙壁体现垂直或倾斜法向，街道则作为建筑之间的地表空间。Urban 还可以与植被类型组合，从而表示建筑街区中的均质植被、行状植被或树冠植被。

### 四种 Vegetation type

**Bare soil：裸土或无植被地表**

Bare soil 不引入叶片层，辐射主要由土壤或基础地表发射率和温度决定。该模式适用于裸地、道路基础面或作为其他场景的参考背景。裸土还可以选择 Hapke/Thapke 方向性修正，用于描述土壤发射率随观测角度变化的情况。

**Turbid veg：均质或浑浊植被层**

Turbid vegetation 将植被视为统计意义上的均质叶片层，主要由 LAI、hotspot 参数、叶片发射率、土壤发射率和日照/阴影温度控制。它适合描述连续冠层、草地和较均匀的农田植被，也是进行方向性冠层分析时最常用的基础模式。

**Crop rows：垄行作物**

Row 模式显式加入作物行宽、行间空隙、作物高度和行方向。与均质植被相比，垄行场景具有更强的方位异质性：当观测方向与作物行平行或垂直时，叶片、土壤和行间空隙的可见比例会不同。因此，Row 特别适合研究农田行结构和方向性观测之间的关系。

**Forest crowns：离散树冠**

Forest crowns 用离散树冠描述林地或稀疏树木场景，可设置树冠水平半径、垂直半径、树冠高度和空间密度。它与均质冠层不同，能够表达树冠之间的空隙、背景地表暴露以及离散目标造成的方向性变化。

## 组合场景的意义

四种 Surface 与四种 Vegetation type 可以形成 16 种组合。例如：

| 地表结构 | 植被类型 | 典型含义 |
|---|---|---|
| Plane | Bare soil | 平坦裸地 |
| Plane | Turbid veg | 平坦均质植被 |
| Slope | Turbid veg | 坡面植被 |
| Terrain | Forest crowns | 起伏地形中的离散树冠 |
| Urban | Bare soil | 建筑、墙壁、屋顶与街道组成的无植被街区 |
| Urban | Turbid veg | 建筑街区中的连续植被背景 |
| Urban | Crop rows | 城市边缘或特殊区域的行状植被 |
| Urban | Forest crowns | 建筑街区中的树木和树冠 |

这些组合不是简单的标签切换。选择不同场景后，模型会改变可用的结构参数、组分温度、发射率和几何贡献。例如，Urban 场景会增加屋顶、墙壁和街道的光谱与温度输入；Row 场景会启用行宽、行距和行方向；Crown 场景会启用树冠半径、高度和密度。

## 光谱输入：热红外逐波段计算

TIRT 使用的是热红外波段，而不是可见光或近红外反射率。输入波长可以直接写在 `input.csv` 中，也可以由波长文件提供。例如：

```text
spectral,wavelengths,8.0;10.5;12.0,observation wavelengths um
```

每个波长可以对应一组独立的发射率。植被场景通常需要叶片和土壤发射率；城市场景还需要屋顶、墙壁和街道发射率。若使用光谱文件，TIRT 会读取文件中的波长和发射率，并将数据插值到目标观测波长。

这意味着 TIRT 不只是把一个固定发射率乘到总辐射上，而是可以在每一个波段分别计算。对于屋顶、墙壁和街道，用户可以分别使用不同的光谱数据；对于叶片和土壤，也可以通过独立文件输入实测或文献光谱。

需要注意的是，发射率必须与热红外计算保持一致。可见光或近红外反射率不能直接当作热红外发射率使用。如果用户只有反射率数据，应先确认其波段范围和物理定义，再决定是否可以转换或用于其他模块。

## 热状态与辐射计算

TIRT 的统一 `run()` 入口将组分温度作为输入。当前模型主要是热红外方向性辐射传输前向模型，因此温度可以按日照和阴影分别指定，例如叶片日照温度、叶片阴影温度、土壤日照温度和土壤阴影温度。城市场景还可以分别指定屋顶、墙壁和街道的日照与阴影温度。

在给定波长和温度后，组分的热辐射可以用普朗克定律表示为：

\[
 B_\lambda(T)=\frac{2hc^2}{\lambda^5}\frac{1}{\exp\left(\frac{hc}{\lambda kT}\right)-1}
\]

实际观测辐亮度则由发射率、组分温度和方向性权重共同决定。用概念形式表示，可以写成：

\[
 L_\lambda(\Omega)=\sum_i w_i(\Omega)\,\varepsilon_i(\lambda)\,B_\lambda(T_i)+L_{\lambda,\mathrm{reflected}}(\Omega)
\]

其中，\(i\) 表示叶片、土壤、屋顶、墙壁或街道等组分，\(w_i(\Omega)\) 表示该组分在观测方向 \(\Omega\) 下的方向性贡献，\(\varepsilon_i(\lambda)\) 是逐波段发射率，\(T_i\) 是组分温度。计算得到的辐亮度可以进一步通过普朗克反演转换为亮温。

这个表达式也说明了为什么不能只看一个组分的温度：即使墙壁温度较高，如果墙壁在当前观测方向中占比很小，最终辐亮度仍可能主要由街道或植被决定。反过来，墙壁面积较大、观测方向接近墙面法向时，墙壁会对结果产生更强贡献。

## 观测几何与方向性结果

TIRT 支持多种观测角度组织方式。最直接的方式是在 `input.csv` 中给出 VZA 和 VAA；也可以使用文件读取一组观测方向，或者自动生成太阳主平面和垂直太阳主平面。

主要角度包括：

- `SZA`：太阳天顶角；
- `SAA`：太阳方位角；
- `VZA`：观测天顶角；
- `VAA`：观测方位角；
- `RAA`：相对方位角，由观测方位与太阳方位之间的关系得到。

在太阳主平面中，观测方向通常对应相对方位角 0° 和 180°；在垂直太阳主平面中，通常对应 90° 和 270°。TIRT 还可以读取半球方向文件，按照不同天顶角和方位角生成完整方向场。

方向性输出可以用于绘制三类图形：极坐标方向图、太阳主平面曲线和垂直太阳主平面曲线。这些图形能够帮助用户判断热点效应、阴影效应、冠层遮挡、坡向效应以及城市立面方向效应。

## 城市场景：屋顶、墙壁与街道

城市场景是 TIRT 与普通均质地表模型的重要区别之一。建筑表面不能被简单地当成一块水平土壤，也不能用同一个平均发射率和平均温度代替所有部分。

屋顶、墙壁和街道应分别提供光谱与热状态。屋顶通常更容易接收到直接太阳辐射，但最终辐射仍受到屋顶材料发射率、温度和观测投影关系影响。墙壁的可见性受建筑朝向和传感器方位影响，墙面太阳入射投影也应依据太阳方向与墙面法向之间的夹角计算。街道则位于建筑之间，往往具有更强的遮挡和不同的天空辐射条件。

因此，城市结果分析不能只看一个“urban temperature”。更有意义的做法是同时查看：

1. 屋顶的逐波段发射率、辐亮度和亮温；
2. 墙壁的逐波段发射率、辐亮度和亮温；
3. 街道的逐波段发射率、辐亮度和亮温；
4. 不同观测方向下三类组分的相对贡献；
5. 城市与植被耦合时，植被是否遮挡或改变建筑组分的可见比例。

需要强调的是，TIRT 的当前统一入口主要负责给定热状态下的辐射传输计算。它并不自动替代完整的城市地表能量平衡模型，也不应把输入的固定温度误解为模型已经通过感热、潜热和地表热通量求解出的平衡温度。如果需要研究建筑内部传导、空气动力学阻抗、感热、潜热或地表热通量，应使用或接入相应的能量平衡模块，再把得到的表面温度传给 TIRT 进行方向性辐射计算。

## GUI：从输入设置到三维预览

TIRT 提供本地浏览器 GUI。启动本地服务后，用户可以在网页中设置场景结构、太阳和观测角度、波长、发射率、组分温度以及几何文件。Three.js 三维场景用于显示地表、坡面、地形、建筑、植被、太阳和观测方向，帮助用户在运行前检查场景设置是否符合预期。

GUI 的运行流程可以概括为：

1. 选择 Surface mode，例如 Plane、Slope、Terrain 或 Urban；
2. 选择 Vegetation type，例如 Bare soil、Turbid veg、Crop rows 或 Forest crowns；
3. 设置与当前场景相关的结构参数；
4. 输入太阳角度、观测角度和波长；
5. 输入或上传叶片、土壤、屋顶、墙壁和街道光谱；
6. 输入日照和阴影组分温度；
7. 点击 Run simulation；
8. 在结果区域查看亮温、辐亮度、观测表格和方向性图形；
9. 需要复现时保存当前生成的 `input.csv` 和输出表格。

GUI 后端仍然调用项目根目录的统一 `run()` 函数，因此网页运行结果与命令行和 Python 调用使用同一套计算入口。这种设计可以避免 GUI 中出现一套独立算法，也便于对比脚本计算、批处理计算和交互式计算的结果。

## 命令行和 Python 调用

TIRT 可以直接通过命令行运行：

```bash
python run.py --input input.csv --output cases/demo/output.csv
```

也可以在 Python 中调用：

```python
from run import run

output_path = run("input.csv", "cases/demo/output.csv")
print(output_path)
```

这种统一入口适合批量改变 SZA、VZA、VAA、波长、LAI、发射率或场景结构参数，自动生成多组观测结果。结果文件以“观测方向 × 波段”为基本记录单位，包含场景信息、太阳和观测角度、各组分发射率、辐亮度以及开尔文和摄氏度亮温。

对于研究工作，建议把每一次模拟使用的 `input.csv`、输出 `output.csv`、光谱文件、几何文件和绘图结果放在同一个 case 目录中。这样可以明确追踪参数来源，避免只保存一张最终图片却无法复现计算过程。

## 如何进行结果检查

热红外模型的输出不能只凭“数值看起来像温度”来判断。推荐按照以下顺序检查。

首先，检查波长。确认输入的是热红外波段，波长单位为微米，并且光谱文件覆盖了目标波段。其次，检查发射率范围，通常应位于 0 到 1 之间；不同组分应使用与材料对应的发射率，而不能把土壤、屋顶和墙壁全部设置成同一个值。

然后，检查几何。确认 SZA、SAA、VZA、VAA 的单位均为度，确认相对方位角和太阳主平面的定义一致。对于墙壁和屋顶，还应重点检查建筑方位、墙面法向和观测方向之间的关系。

接着，分别查看各组分温度。城市场景中屋顶、墙壁和街道必须分开检查；植被场景中则应区分叶片和土壤，并区分日照与阴影状态。最后，再查看亮温和辐亮度随观测角度的变化，判断方向性是否与场景结构相符。

一个很实用的验证方法是先运行 Plane + Bare soil，再逐步增加复杂性：先加入均质植被，再加入坡面，之后加入复杂地形，最后测试 Urban 及 Urban + Vegetation。每增加一种结构，都保留上一阶段的输入和输出作为对照。这样更容易定位问题来自光谱、温度、几何还是场景组合。

## TIRT 的应用价值

TIRT 可以服务于多种研究和工程工作。

在遥感算法研究中，它可以生成不同观测角度下的模拟亮温和辐亮度，用于分析方向性误差、角度归一化和多角度反演。在地表热环境研究中，它可以比较植被、土壤、建筑和街道在不同太阳条件下的热红外表现。在城市遥感中，它可以帮助研究屋顶、墙壁、街道以及城市植被对传感器信号的共同影响。

在实验设计中，TIRT 可用于估计需要采集哪些角度、哪些波段和哪些组分温度。在教学和模型验证中，Plane 和 Bare soil 提供了清晰的基准场景，Slope、Terrain、Row、Crown 和 Urban 则可以逐步引入复杂因素。在软件工作流中，GUI 适合交互式探索，`run()` 和 `input.csv` 适合可重复计算，绘图模块适合结果整理。

## 当前边界与后续方向

任何方向性辐射传输模型都需要明确自己的边界。当前 TIRT 统一入口的优势是场景组合清晰、输入输出结构统一、可以逐波段和逐方向计算，并且能够在本地 GUI 中直接观察场景和结果。它的热状态主要由输入文件给出，因此特别适合前向模拟、敏感性分析和与外部能量平衡模型耦合。

如果要进一步扩展，可能的方向包括：将完整的短波和长波环境辐射场引入城市组件；把建筑墙体的多层导热与室内边界条件接入表面温度求解；将空气动力学阻抗、感热、潜热和地表热通量纳入统一能量平衡；增加更真实的建筑几何、街道天空可见因子和多次反射；支持更多实测光谱和多时间步气象驱动。

这些扩展不应改变 TIRT 的基本原则：每一个物理量都应有明确的定义，每一个组分都应有独立的光谱和热状态，每一个方向性贡献都应能够追溯到太阳几何、观测几何和场景结构。

## 结语

TIRT 的意义不只是把温度转换成亮温，而是建立一条从“场景结构”到“方向性热红外观测”的可解释计算链。它把平面、坡面、地形和城市建筑放在统一框架中，也把裸土、均质植被、垄行作物和离散树冠放在统一的植被框架中。通过逐波段光谱、逐方向几何和组分温度的组合，用户可以更清楚地理解一个观测值究竟来自哪里。

对于实际使用，最推荐的路径是从简单场景开始，保存每一次输入和输出，逐步加入地形、植被和建筑结构，并结合 GUI 的三维预览、方向性图形以及输出表格进行交叉检查。这样，TIRT 不仅是一个可以运行的程序，也是一个可以用于解释、验证和扩展热红外方向性观测的研究工具。
